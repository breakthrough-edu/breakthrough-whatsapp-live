# Playbook: 写一个真人的档 (person dossier)

一句话: 让主人下次跟这个人见面或回讯息前, 三分钟内知道他是谁、卡在哪、要什么、怕什么、走到哪、**下次该问什么**。写给一个没读过对话的人, 包括三个月后的主人自己和下一个 session。

这份 playbook 同时是机器的规格: WhatsApp Live 的档案 run 每次把这份整份喂给模型 (config `dossier.model`), 任何 session 说「帮 X 重写档」也照它跑。规矩只有这一份; 档头长什么样归你 vault 宪法 §8 的 `person` 族, 这里不复述。码读的是你 vault 里这一份 (config `paths.person_playbook`); 读不到才退回 kit 里的种子, 而且会在 log 与日报里大声说。

下文两个字眼:

- **主人** = 装这套、拥有这个 vault 与这支 WhatsApp 号码的人; config 的 `owner_label` 是档里怎么称呼他。
- **`<marker>`** = 主人的缩写 (config `owner_marker`, 2 到 6 个英文字母)。写进档里的是缩写本身: 例如缩写是 `AB`, 就写 `🗣 AB 2026-09-14`, 手记那节就是 `## AB 手记`。

骨架是第一份试片定的, 前四节的问法承接 customer avatar 常用的四段 (Demographic · Core Problem · Primary Transformation · Market Specifics), 但**规矩反过来**: avatar 写一群人, 每格五句填满算做完; 真人档写一个人, 空格不补, 推的要标。

## When to run it

- **开新档**: 一个人在 WhatsApp 里聊到问价、问日期、问怎么买以上 (stage 到 `dossier.auto_open_min_stage` 或更往前, 默认 `talking`), 而且这条对话的世界列在 `dossier.auto_open_worlds` 里, People 房还没有他的档。`dossier.auto_open_worlds` 默认是空的, 也就是只在主人叫时开; 装 C4 那站时问主人哪几条生意线要自动开。家人朋友 (非生意的世界) 不自动开, 主人说才开。事实来源发现「付了钱、有对话、没档」也算。
- **重写**: 有档的人白天不跟着讯息重写 (会拿到半截对话, 也会撞到主人手改)。每晚一次 (`dossier.nightly_at`, 默认 02:30): 当天来往 `dossier.nightly_min_msgs` 封以上 (默认 5) 或阶段变了的才重蒸, 一晚最多 `dossier.nightly_cap` 份 (默认 8), 超过 `dossier.stale_days` 天 (默认 14) 没重写但有动静的补一次。同一个人 `dossier.min_gap_hours` 小时内 (默认 6) 不重排。
- **主人叫**: 板上按开档或重写档, 或在任何 session 说「帮 X 开档 / 重写 X 的档」: 马上跑, 不受夜批与间隔限制。
- **主人讲一段话** (「更新 <名字> 的档: …」): 听到的那个 session 熟读整份档, 把话融进对应的节 (每处标 `🗣 <marker> <日期>`, ⬜ 被答了就改成事实), 手记那节留一行原话当出处, 只动跟这段话有关的格, 不整份重写; 触发句与步骤住主人 Command Base skill 的 update-person 模式, 验收跟重写同一份。
- 群里他讲的话: 只往本人档追加近况一行 (标「在 <群名> 说」), 不触发重写, 不动 stage。

## What to weigh

照抄步骤的人会做错的, 全在这一节。

- **只写他自己讲的、看到的、和标了推论的。** 🗣 他讲的带时间, 原话照抄不润饰, 语音标 (语音); 👁 看到的是行为或记录; 🤔 推的一定要说得出是从哪句 🗣 / 👁 推的, 说不出的删。没有标记的句子不准出现: 不标的话, 三个月后「推的」会被下一场当成「他说的」。
- **空格不补, 空格就是下次要问的。** ⬜ 是情报, 不是缺陷; 恐惧的身份层 (L3) 没证据就空着, 年龄不猜, 转化后的话没转化就该空。「⬜ 下次见面要问的」那节全部从空格长出来, 是整份档最有用的部分, 不准空。
- **别人对话里的内容只准影响判断, 不准进他的档。** 群里对他的指认可以当 👁, 要注明「<谁> 在 <群> 指认」。健康、家庭冲突、跟这笔关系无关的私事不写; 他自己讲的、会影响这笔生意的 (结婚、现金紧、生意赚不赚) 可以写, 档尾那行私事提示必须在: 一对一里讲的私事, 不出现在任何对外的东西上, 包括从这份档蒸馏出来的 avatar 与文案。
- **主人写的一律保留, 而且验收要验内容, 不只验链接。** 重组时, 原档里主人的观察与判断搬进对应的节, 标 👁 或 🤔 并注「主人 <日期> 记」; 段首有 `<!-- <marker> -->` 的段落原样不动; 原档的 wiki 链接、「这份档的备注」里每一条 bullet 与每个子节标题都要还在, 掉一条整份退回。第一次夜批重写一份档, 就掉了「这份档跟 avatar 差在哪」整整一节, 链接检查却全过, 这一条就是这么来的。
- **stage 你只提议, 不裁决。** 只准往前; 「成了」(`won` 以上) 只认付款记录, 对方说 paid、团队说收到款都不算; 一个人同时有几条线, 写现在最要紧的那条。不带 stage 角色的人不写 stage (哪几个角色带 stage, 跟宪法 `person` 族的角色清单一起定, 常见的是 `lead` · `member` · `client`)。
- **「怎么跟他讲话」那节是写给下一封讯息用的, 不是性格分析。** 每格从他的讯息数出来 (👁) 或指得出是哪几句 (🤔); 「下一封怎么开口」那句要具体到能直接照着写: 用什么口吻、先讲什么、别讲什么。写不出就 ⬜, 不要用「真诚沟通」这种谁都适用的话填。
- **料少的人档就短。** 只有十几封的人 40 到 80 行, 大半 ⬜, 那是对的; 有料的人 150 到 250 行。不要硬撑, 撑出来的都是编的。
- **验收抽原话回原文核。** 抽八句 🗣 回对话包找, 命中低的先人工看; 低的多半是 🤔 引号或主人手记的转述, 不是编的, 但要人眼确认过才放。语音 transcript 是 raw 未校正, 引到对外文案前要重听。
- **档头合不合法是另一件事**, 归宪法 §8 `person` 与它的读器; 这里只管内容。

## The moves

这一节写成机器能直接吃的样子 (档案 run 整份喂给模型), 人照做也一样。

### 材料

- 这个人 `dossier.pack_days` 天 (默认 30) 的 WhatsApp 一对一原文 (语音已转字, 图片给路径, 报价 / 截图那类承重的图可以开来看)。
- 现有的档 (有的话, 整份)。
- 第二大脑里跟他有关的档 (人物档档头的 `wa_jid` 硬配, 加上分数 60 以上的候选整份开)。
- 分诊板对这条对话的 world / stage / priority 与滚动摘要 (只当索引, 事实以原文为准)。
- 事实来源给这个人的系统记录节 (有才有, 规矩见下面第 11 条)。

### 出处标记 (每一格都要有)

- 🗣 **他自己讲的**: 带时间 `(MM-DD HH:MM)`, 长句可引原话 (原话照抄, 几种语言混着讲就照混, 不润饰)。语音转字标 `(语音)`。
- `🗣 <marker> <日期>` **主人亲口讲给这份档的**: 写成 `🗣 <marker> 2026-09-14` (或 `🗣 <marker> 9/14`), 不带钟点。最高来源, 跟对话冲突以主人为准, 两边都写 (「`🗣 <marker> 9/14` 说 X; ⚠️ 对话里他 09-10 说 Y」)。重写时措辞可以改, **标记与日期要留在同一节** (验档器逐节核, 掉一处整份退回)。⚠️ 对话里引主人讲的话, 照一般原话写 `🗣 <marker> 09-12 13:09` (带钟点), 那种不上锁。
- 👁 **看到的**: 行为或记录 (他几点来、报名填了什么、用什么设备、语气习惯)。
- 🤔 **推的**: 判断, 不是事实。每个 🤔 后面要说得出是从哪句 🗣 / 👁 推的。
- ⬜ **还不知道**: 空格。不补, 不编, 不用「可能」填。

### 骨架 (照这个顺序, 节名照抄; 没料的节留着并写 ⬜)

⭐ 下面栅栏里每个 `## ` 标题, 就是验档器认的节名: 验档器每次从这里现读, 码里不另抄一份。我们默认这样, 因为节名抄两处一定会漂: playbook 改了名, 验档器还认旧的, 每份新档都被退回。标题尾巴的括号注解可留可省; 标题下面注解写了「这节可以没有」的才可以缺, 其余缺一节整份退回。⚠️ 改节名前先知道: 有几个节名或格名, 码还要按用途认 (待问清单、备注、手记、WhatsApp 近况、系统记录、「下一封怎么开口」那句), 它们在 config 的 `person.section_roles` 里各对一个名字, 所以改这里的节名, 要在 `person.section_roles` 同步改成同一个字, 不然备注与手记的保护会找不到节而静默不验。旧档里那一节的标题也要一起改, 不然那节带的 `🗣 <marker>` 标记在第一次重写时, 会被当成搬了节而退回。

# <名字>

> 两三句引言: 他是谁 · 怎么认识 · 现在走到哪 · 手上有什么 (码 / task / 承诺)。

**出处标记**: 🗣 他自己讲的 (带时间) · 👁 看到的 · 🤔 推的 (不是事实) · ⬜ 还不知道 (= 下次要问的)
料源: <哪段时间的 WhatsApp 一对一, 几条语音转字; 加哪些 vault 档>

## 1 · 他是谁
| 名字 | 生意 | 规模 | 他在公司的角色 | 家里 | 钱的姿态 | 讲什么话 | 设备 | 他心里那句没讲出口的 (🤔) |
(表格, 一格一行; ⛔ 没有「年龄」这格, 真人不猜年龄。最后那格是 avatar 的 emotional anchor, 后面每一节都要能指回它, 没证据就 ⬜)

## 2 · 他的问题
- 表面 → 真正 (🤔, 一句话, 要指出从哪几句推的)
- 场景 (全部 🗣, 一句没编; 有几个写几个; 场景本身就是情绪, 不写「他很焦虑」)
- 恐惧: L1 具体怕的 / L2 意味着什么 (🤔) / L3 身份层 (⛔ 没证据就 ⬜, 不准替他讲)
- 关系怎么被影响 (太太 / 伙伴 / 员工 / 客户 / 他对自己讲的话; 没证据的格 ⬜)
- 试过什么, 为什么没用 (🗣, 方案要具体到名字)
- 他不肯做的 (产品设计的红线: 他不肯做的事, offer 就不能要求他做)

## 3 · 他要的结果 (他自己描述的, 不是我写的)
- 近的那个 · 远的那个 · 具体的第一个任务 · 转化后的话 (还没转化就 ⬜, 而且应该空)

## 4 · 市场与异议
- 他认为做到什么就算成了 (他的 X) + 这个 X 跟主人实际交付的有没有落差 (🤔; 错的 X 就是 positioning 的入口)
- 放弃这个问题要付什么代价 (🤔, 标清楚是推的: 要放弃的身份 / 要承认的事 / 要改的习惯)
- 嘴上怪谁 vs 心里怪谁 (没证据 ⬜; 「他不抱怨」本身是 👁)
- 他的异议 (表格: 异议 · 原话 · 背后真正的顾虑 🤔 · 有没有被解掉)

## 5 · 现在的状态与下一步
- 他最后说的 (🗣 带时间) · 手上有什么 (码 / 报价 / 链接, 👁) · 悬着的 (⬜) · 跟进走哪张 task (有就链)
- world / stage / priority 现在是什么 (从分诊板抄, 带日期)
- ⬜ 系统记录 (事实来源给的: 付过什么 / 报过什么 / 来了没; 没有就写 ⬜)

## 6 · 怎么跟他讲话
(对症下药的沟通对策: 分诊脑写草稿时照这节写, 板上显示最后那句)
| 格 | 写什么 |
|---|---|
| 语言与语域 | 用哪几种语言、各占多少、口语或方言深浅、用不用 emoji、称呼 (主人叫他什么、他叫主人什么) (👁 从他的讯息数出来) |
| 讯息形态 | 他发长还是短、语音多不多、几点活跃、回得快不快、连发几封 (👁) |
| 直接还是铺垫 | 他问问题直问还是绕; 直接讲价他会不会缩; 他要数字 / 案例 / 别人的话才动 (🤔, 指出从哪几句推的) |
| 什么话他会接 | 他回得快、回得长、主动问的话题 (👁) |
| 什么话他会缩 | 他没回、只回 ok 的话题; 他明说不喜欢的 (👁 / 🗣) |
| 禁区 | 别提的: 别人对话里知道的事、他讲过不想被提的私事、上次踩过的 (🗣 / 👁) |
- **下一封怎么开口**: 一句话, 用什么口吻、先讲什么、别讲什么 (🤔 综合上面; 例「先答他那个价钱的问题, 一句给数字不铺垫; 中文为主, 不用 emoji」)。料少就 ⬜, 但这一行尽量写。

## ⬜ 下次见面要问的
编号列表, 全部从上面的 ⬜ 长出来。这一节是整份档最有用的部分, 不准空。某一题被答了 (对话包里他讲了, 或主人讲了 🗣 <marker> <日期>) 就把答案写进它该在的那一格、那一题删掉重新编号, 不留 ⬜。

### 写死的规矩

1. **只写他自己讲的、看到的、和标了 🤔 的推论。** 不准写对话包与 vault 里没有的事。不准用别人对话里的内容 (那是别人的私事; 群里对他的指认可以当 👁, 要注明「<谁> 在 <群> 指认」)。
2. **健康、家庭冲突、跟这笔关系无关的私事不写。** 他自己讲的、会影响这笔生意的可以写, 档尾固定那行私事提示要在。
3. **主人写的判断保留。** 重组现有档时: 原档里主人的观察与判断, 一律搬进新骨架对应的节 (标 👁 或 🤔, 注明「主人 <日期> 记」), 事实按新证据更新并带出处, 出入的地方两边都写并标 ⚠️。段首有 `<!-- <marker> -->` 的段落原样保留不动。原档的 wiki 链接 (`[[...]]`) 全部保留。「这份档的备注」里每一条 bullet 与每个 `###` 子节原样搬到新档同一节, 一条不准删, 可以在后面加。

    3b. **主人讲的认得出来, 一个都不准掉。** 带 `🗣 <marker> <日期>` 标记的句子 (`🗣 <marker> 2026-09-14` 或 `🗣 <marker> 9/14`) 是主人亲口讲给档的, 最高来源: 重写时措辞可以改, 标记与日期留在同一节 (同一节同一天几处就留几处); 跟对话包冲突以主人为准, 两边都写。⚠️ 对话里引主人的话带钟点 (`🗣 <marker> 09-12 13:09`) 的那种不算, 照一般原话处理。「`## <marker> 手记`」每一行一个字不改、原样留在那节, 不准挪进别的节; 只有占位行 (`(还没有)` · `⬜ …`) 可以换掉。验档器逐节核标记、逐行核手记, 掉一处整份退回。

    3c. **⬜ 被答了就改成事实, 不留 ⬜。** 「⬜ 下次见面要问的」某题被对话包或主人 (`🗣 <marker>` 标记的句子、手记) 答了, 就把答案写进它该在的那一格 (带出处), 那一题删掉、后面重新编号; 格里的 ⬜ 同理换成带出处的事实。还没答的照留, 清单不准空。
4. **空格不补。** ⬜ 是情报不是缺陷; 填不满的节照样留着。
5. **每个 🤔 要说得出根据。** 「他两次主动讲自己不是 engineer」这种才算; 没根据的推论删掉。
6. **stage 你只提议, daemon 裁决**: 只准往前; `won` / `active` / `done` 只认付款记录或原档已在那几格, 否则封顶 `offered`; 不带 stage 角色的人不写 `stage` 与 `stage_since`。(这几个是默认词表的字; 主人改过 `vocab.stages`, 照他的。)
7. **档头只准用宪法 §8 `person` 族的键, 一个不准多**: 规格外的键整份退回 (几个常见的无害多余键, 例如 `tags` · `aliases` · `email`, 验档器会剥掉并记 log, 但不要写)。`wa_jid` 与 `since` 不准改, `wa_jid` 不加引号照原样抄; `roles` 只准用闭合清单的值 (清单与每个值的意思只看宪法那段; 原档的只补不删, 修饰进 `roles_remark`), 写成一行 `roles: [member]`; `won` 不由写档的人写 (见第 6 条); `dossier_updated` daemon 自己填。
8. **档名不改** (`<Name>.md` 照旧), H1 可以补全名或称呼 (例 `# 全名 (称呼)`)。
9. **标点照主人 vault 的家规**: 他的 CLAUDE.md 或宪法有写就照写 (例如有的家规不准 em dash、不准用双连字号或前后带空格的连字号当分隔)。中英或几种语言混排, 照主人与对方的习惯。
10. **长度**: 有料的人 150 到 250 行; 料少的人 40 到 80 行, 大半是 ⬜, 那是对的, 不要硬撑。

    10b. **节一节不准少** (上线首晚三份新档被退回的病根之一): 骨架里每个 `## ` 节都要在, 顺序照骨架, 料少的人每格写 ⬜ 也要把节写出来; 只有注解写「这节可以没有」的能缺。
11. **「## 系统记录 (自动)」是机器给的, 不是写档的人写的。** 机器给了整节 (从标题到 `<!-- facts:end -->`) 就原文照放, 位置在「## WhatsApp 近况 (自动)」之前, 一个字不改、不加行、不删行、不换标记 (验档器逐字核, 动了整份退回); 机器没给就整节不写, 也不准自己写一节或自己放 `<!-- facts:begin -->`。里面的事实 (付了什么、报了什么、来了没) 可以拿来写第 1 节与第 5 节的判断, 标 👁 并注「系统记录」; ⛔ 不准编表里没有的: 没给付款就不能写他付了, 对方嘴上说 paid 也不算。

### 落地 (谁跑都一样)

验档头 (宪法 §8 `person` 的读器) → 验内容 (原档链接、备注节每条、`<!-- <marker> -->` 锁段、手记每一行、`🗣 <marker>` 标记都在, 节一节不少) → 抽八句原话回原文核 → 旧版备份三版 (默认在 `live/dossier-backups/<档名>/`) → 放进 People 房 (`paths.people_dir`): 放之前重读一次目标档, 跟开跑时读到的不一样就不盖 (只是近况区块多了新行的, 把新行带进候选再放), 目标档已经存在而这次是当成新档跑的, 拒绝, 不盖 → filing-log 一行 (`paths.filing_log`; 没设而 `paths.vault` 有设, 就是 vault 里的 `99_Meta/filing-log.md`) → 这个夹的门登记一行 (一场 session 做的一批登一行; daemon 夜批自己放的档不逐份登, filing-log 就是它们的索引)。
