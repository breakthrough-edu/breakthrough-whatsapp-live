# Feature checklist

Every feature WhatsApp Live has, one row each, with how to prove it on an installed system and what passing looks like. It is the public acceptance list: station O11 walks it with the owner, and an independent session walks it again with evidence. Nothing is called done while a row is failing or unverified.

The code is the source of truth. Every probe below names a command, a log line, a file or a selftest check that exists in this payload; when a probe and the code disagree, the code is right and this page needs fixing.

## Before you verify

Run probes in Terminal on the always-on Mac. Claude Code keeps no shell variables between commands, so paste this block in front of each probe, with each `<...>` filled exactly as the header of `<home>/INSTALL-PROGRESS.md` records it (a test install's own values for a **test install** row). `paths.home` is an absolute path there, because a `~` inside quotes is not expanded.

```sh
KIT=~/.claude/skills/breakthrough-whatsapp-live      # the folder holding SKILL.md, install/ and daemon/
HOME_DIR="<paths.home from the progress file header>"
LIVE="$HOME_DIR/live"
PY=/usr/bin/python3
LABEL="<launchd.label from the progress file header>"
ILABEL="$LABEL.intake"
PORT="<board.port from the progress file header>"
case "$HOME_DIR $LABEL $PORT" in *"<"*|"~"*) echo "fill in HOME_DIR, LABEL and PORT first (HOME_DIR as an absolute path)" >&2; exit 1;; esac
READER="$KIT/skills/breakthrough-whatsapp-read/scripts"
DOSSIER="$KIT/skills/breakthrough-person-dossier/scripts"
WADB="$HOME/Library/Group Containers/group.net.whatsapp.WhatsApp.shared/ChatStorage.sqlite"

cfg()    { "$PY" -c 'import sys
sys.path.insert(0, sys.argv[1] + "/daemon")
import wa_common
c = wa_common.load_config(sys.argv[2])
for k in sys.argv[3].split("."):
    c = c[k]
print(c)' "$KIT" "$LIVE/config.json" "$1"; }                                   # one config value, defaults filled
q()      { sqlite3 -readonly -separator ' · ' "$LIVE/state.sqlite" "$1"; }      # read the state database
logs()   { cat "$LIVE"/wa_live.log.3 "$LIVE"/wa_live.log.2 "$LIVE"/wa_live.log.1 "$LIVE"/wa_live.log 2>/dev/null \
             | grep -F -- "$1" | tail -n "${2:-3}"; }                           # newest log lines holding a text
apij()   { curl -s "http://127.0.0.1:$PORT$1" | "$PY" -c 'import json, sys
d = json.load(sys.stdin)
print(eval(sys.argv[1]))' "$2"; }                                               # one expression over a board JSON endpoint
fj()     { "$PY" -c 'import json, sys
d = json.load(open(sys.argv[1], encoding="utf-8"))
print(eval(sys.argv[2]))' "$1" "$2"; }                                          # one expression over a JSON file
newest() { ls -td "$LIVE"/runs/"$1"*/ | head -1; }   # newest run folder: 2 (a judgment), dossier-, probe-, second-source-, backfill-
nodepid() { launchctl print "gui/$(id -u)/$LABEL" | awk '$1 == "pid" && $2 == "=" {print $3; exit}'; }   # the node parent launchd started
```

How to read a row:

- **How to verify** is a command, a board observation (`board:`, on the desktop browser or on the phone), or a selftest check (`selftest:` names the module and the check; it passes when that line of the module's `--selftest` starts with `ok` or `✓`).
- **(model call)** spends a little usage. **(network)** reaches the owner's tool (Lark, a CSV link, the push service). **(test install)** runs only on a separate install with its own `paths.home`, `launchd.label` and `board.port`, both gate policies at `skip`, pushes into a file and a throwaway vault, never on the install that reads the owner's real chats (`install/O11-observation-and-acceptance.md`, step 5).
- 📸 marks a row whose evidence is a screenshot. Screenshots show other people's messages: keep them in `$HOME_DIR/acceptance/` (0700), never in the vault, and delete them when the audit is done.
- A row that copies a note, or restores one from a backup, does it with the Read and Write tools, never with `cp` or a `>` redirect: the owner's my-second-brain frontmatter guard refuses a shell command that pairs `cp`, or `cat`, `tee`, `printf` or `echo` with a `>`, with a path ending in `.md`. A probe that writes a file puts it under `$HOME_DIR/acceptance/`, never into a run folder a later row reads.
- The daemon logs in Chinese. Quoted log lines are exact, with `<...>` where a value goes.
- Placeholders: `<jid>` a one-to-one test chat (`apij /api/board '[(r["name"], r["jid"]) for r in d["rows"]][:10]'` lists them), `<group jid>` a test group, `<note>` a person note's file name without `.md`, `<dest>` the value of `backup.dest`, `<date>` a `YYYY-MM-DD` day.
